# 代码审查 Skill

为 AI 编码助手提供统一的代码审查规范和输出格式。

## 审查流程

1. 通读变更，理解整体意图
2. 逐文件检查，关注逻辑和边界
3. 汇总问题，按优先级分类
4. 输出结构化审查报告

## 审查维度

按优先级从高到低检查：

### 1. 安全性与正确性（阻塞级）
- 注入风险（SQL、命令、模板）
- 敏感信息泄露
- 权限检查缺失
- 数据丢失/损坏风险
- 并发竞态条件

### 2. 逻辑与边界（阻塞级）
- 空值/null 未处理
- 异常吞没
- 边界条件遗漏
- 死循环风险

### 3. 可维护性（建议级）
- 命名是否清晰
- 函数是否过长
- 重复代码
- 过度复杂的逻辑

### 4. 性能（建议级）
- 不必要的循环/查询
- 内存泄漏风险
- 阻塞操作

### 5. 测试与文档（建议级）
- 核心逻辑缺少测试
- 公开 API 无文档
- 变更未更新文档

## 输出格式

审查报告按以下结构组织：

```markdown
## 代码审查报告

### 概述
总体评价，1-2 句话。

### 阻塞问题 🔴
必须修改。每条包含：文件位置、问题描述、修改建议。

### 建议优化 🟡
建议但非强制。每条包含：文件位置、优化建议、理由。

### 亮点 👍
写得好的部分，值得推广。

### 提问 💬
需要澄清的问题。
```

## 审查原则

- 对事不对人
- 提供具体建议，不笼统评价
- 区分阻塞和建议
- 发现好的代码也给予认可
